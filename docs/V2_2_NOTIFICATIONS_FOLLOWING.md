# SwipeBuy V2.2 — Notifications + Following Feed

## Added
- Firestore-backed notifications stream.
- Mark-notification-as-read flow.
- Per-user device-token storage foundation.
- Following provider feed service.
- Following page with pull-to-refresh.
- Production architecture notes.

## Data model
`notifications/{notificationId}`
- userId
- title
- body
- type
- read
- createdAt
- optional listingId/providerId/orderId

`users/{uid}/devices/{token}`
- token
- platform
- updatedAt

## Production requirements
- FCM/APNs sending must happen from a trusted backend, never from Flutter.
- Device tokens should be validated, rotated and deleted when invalid.
- Notifications should be generated by trusted backend events (follow, like, comment, order, booking, application, payment).
- Add notification preferences and quiet hours.
- The current following feed performs one Firestore query per followed provider. For scale, replace it with a server-created denormalized feed / fan-out or dedicated feed index.
- Keep ranking and notification eligibility server-controlled.
